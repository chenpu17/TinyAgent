# run_code v2：awclean 编排成本优化

日期：2026-09-11。契约版本：`run-code-routing-v2`。

本页保留 v2 记录。[v3 单项实验](run_code_routing_v3.md)未达到减少模型往返的目标，已归档并恢复 v2；v2 原始契约及构建指纹保存在该臂 pilot.json。

v1 两题探针证明触发入口可工作，但 awclean 的成本没有改善：首次长程序误把 `{response: [...]}` 当数组，整段代码重生成后才成功，且存在完整集合日志和代码外重复验证。v2 针对这条执行路径优化，不改变触发判据或系统提示词。

## 改动

1. 常驻 `tools.call` 描述明确：JSON 解析不等于业务信封解包，`{response:[...]}` 要取 `.response`，循环前确认形状。描述仍在上限内：1198 字符。
2. 技能正文最前面增加短小的 `responseRows` 局部函数示例，接受已确认契约的裸数组或 response 数组；缺字段、null、错误对象和其他形状必须报错，不能以 `|| []` 伪装空页。该函数不是新增内置 helper，也不是业务成功校验器：接口另有成功/错误状态时，仍须先按该接口契约验证；分页终止独立按真实接口规则判断。
3. 明确复用已有响应形状证据，不固定多加探针。只有形状未知时才先写短小只读代码；只写当前任务需要的流程，不照抄完整框架。
4. `console.log` 与 `return` 同样只输出摘要；文件只在续批、恢复或任务需要时保存，不能猜不存在的 `delete_file`。
5. 一次完整列表已经包含目标状态与保留集合所需字段时，以集合内容比较完成校验；字段不足才补查。代码已完成独立最终读回且没有新写入/新疑点时，直接用该摘要，不在外层重复读取。必须检查集合成员，不能只比较数量。

skill 全文由 v1 的 9184 增至 10248 字符，这是额外手册成本，不能仅凭“提示更详细”预设净收益。运行时、prelude、封闭 helper 清单、预检/墓碑文案、schema、teaser 与两个系统提示词均未改变。设计附录及指纹清单已同步。

## 工程验证与检视

- `cargo test --features code,mock` 通过；8 项文档示例回归包含新增响应适配测试。
- 新测试直接提取 skill 的实际函数，在真实 QuickJS 中通过宿主工具返回 JSON 文本：裸数组、response 数组和合法空数组成功；缺字段、null、错误对象、未声明的 items 形状拒绝。共 7 种响应，确认不会把非法形状吞成空页。
- 默认/TUI/code 三组 Clippy `-D warnings`、fmt、契约同步与差异空白检查通过。
- Python/Node 的 code feature 构建及各自测试通过。
- 独立 subagent 只读检视：未发现阻塞本次探针的 P1/P2。特别复核了校验强度、解析适用范围、实验臂隔离和提示词/teaser 不变。

## 复测设计

只跑 `awclean` 一次，使用独立 `ta-code-routing-v2-aw` 臂，继续 `glm-5.3-flash`、on-demand、precheck=false。新旧使用同一个 `agentic-code.md` 和评测答案尾巴；保留 v1 原始结果。实际 read_skill 内容与本版归档契约比对，实际模式从 result.json 核对。

```sh
cargo build --release --features code
python3 scripts/run_code_routing_pilot.py --tasks awclean --run
```

脚本根据 manifest 版本派生实验臂；历史 v1 两题默认探针记录不被覆盖。当前 metadata 同时固定所选任务集合；同一臂改选题会拒绝，需另建批次。执行器的完整配方另受 runner 指纹管理；若未来修改 benchmark 配方，须使用新臂，避免由 runner 将旧同臂结果移入 `.trash`。

v2 的三个程序分别负责收集/计算计划，执行 19 项移除并校验最终曲库集合，最后补查点赞与下载状态。首个程序已按 `.response` 取数组；没有重生成失败的长程序。第三段校验针对未应改变的点赞/下载状态，与第二段的曲库成员校验并非同一事实；不能为节约次数盲目删除。可以进一步将这两类必要校验纳入一次程序，但目前模型仍选择了分阶段执行。

效果属于局部改善：历史直接调用路线三次中位耗时为 145.4s、非缓存输入 16,927、输出 7,226，v2 在这些维度仍更贵。总 token 略低于旧中位 332,912，不能据此宣布新路线整体更省。剩余主要空间是减少重复探查和规划/执行/校验之间的模型往返；本轮不继续改文案再择优重跑，以免把多次尝试中最好的单例冒充稳定效果。

单题、单次迭代探针不构成稳定收益结论，也不能区分响应解析说明和成本纪律各自的因果贡献。尤其 v1 两题并行、v2 单题运行，墙钟还受模型服务响应与运行调度影响；总 token 包含缓存输入，应与非缓存输入和输出分别报告。尚未在 v2 重跑 awlikesong 或其余任务，不能宣称无跨任务回归。
