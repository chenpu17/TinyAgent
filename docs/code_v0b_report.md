## 2. 语料与装置的攻防史（v1 → v1.3，每次泄漏都由实测攻击暴露）

1. **v1**：dev↔holdout 模板帧不相交 + 新噪声型 + e1 偏难移位。首跑即破：
   **glm 主动验证 id 前缀（`h-bug-0007` 式）与 dev label 的 100% 相关，直接
   `label = id.split('-')[1]` 拿满**——规则变难时模型会找元数据捷径。
   修复 = id 不透明（shuffle 后连续号）。
2. **v1.1**：id 修复后 e0 基线 0.49（≈朴素探针水位），但 e0p 一跑用**自写
   正则拿 1.0**——帧不相交只杀逐字迁移，共享基座槽位把类指示锚词
   （退款/验证码/报错/投诉……）近乎无损迁移。修复 = 锚词稀释 35% + 冲突 10%。
3. **v1.2**：deepseek@8192 一跑 1.0——解剖终判器发现它**只查标题表**：每类
   4 个固定标题帧 = 标签预言机，正文难度全部作废（冲突票还被类标题剧透）。
   修复 = 稀释/冲突票标题一律中性、标准票 60/40 → 标题预言机覆盖 1.0→0.33。
4. **v1.3 当前形状**：强手写关键词规则 macro F1 ≈ 0.68；标题预言机 0.33；
   逐字重叠 0；id 不透明。规则层覆盖上限落位，语义残差层（稀释+冲突 ≈ 45%）
   是 llm 路线的价值面——**但残差句池仍是固定小集合（~44 句），外层可逐句
   语义判掉（枚举面，见 §5 基线 0.94 的成因）**。

另两个装置发现：deepseek 会用**频次分析挖出固定噪声池并精确剥离**（合法）；
run_code 沙箱被真实使用（writeVerified 落 predictions + 自校验断言）。

## 3. 装置与协议修正（全部实测驱动）

1. **干预零曝光问题**：门控披露（LIB/BATCH/LLM 段）与 E0′ 边界句全部骑在
   技能正文上。v1.1 批 **6/6 全程零 read_skill**——e0 与 e0p 模型可见面完全
   相同，E0′ 等于没部署；试点 E2 的"门开不用"部分同源（LLM 段从未进上下文）。
   修正 = 协议 v2 任务文本统一加技能拉起句（所有臂同文，非臂变量）→ v1.2 批
   起 **read_skill 100% 生效**。
2. **完成纪律**：任务文本加"先写出完整 predictions 再做总结"。
3. **stream_idle**：网关断流视为基建失败，同 (arm,rep) 重跑一次、两记录都留。
4. **E0′ 指纹门**：e0p 臂跑前 sha256 校验磁盘技能 = 冻结指纹，漂移拒跑。

## 4. 完成墙与外层模型定档

- **glm-5.3-flash 不可用作外层**：v1.2 上 0/7 完成（4096 批 0/6、8192 探针
  0/1）。死因：每轮思考烧 3-4k，**会把给定 cap 烧满（4096→8192 烧钱翻倍、
  结局相同）**——墙是"探索长度 × 思考密度"，提 cap 无解。留作环境定档发现。
- **deepseek-flash @8192 可用**：探针完成（@4096 差最后一步：pred_raw 已
  288/288 valid、acc 0.844，死在格式化轮）。画像：小步多轮（100–1500
  tok/轮）、write_file 真落盘、墙钟 ~135–410s。
- 正式批外层协议 = deepseek-flash @8192（装配文档修订已挂）。

## 5. 主假设首批读数：E0 vs E0′（v1.3，ds@8192，×3 交错）

| 臂 | 完成 | F1（完成跑） | 路由画像 | 死因（未完成跑） |
|---|---|---|---|---|
| e0（内置技能） | **3/3** | 0.9419 / 0.9190 / 0.9674 | run_code 为主力（36/25 次）或 shell+run_code 混合 | — |
| e0p（三问边界句） | **1/3** | 0.8986 | 深度分析（run_code×13 挖噪声池+dev 自校验 192/192）/ shell×30 / shell×22 | 2/3 max_tokens 烧穿 |

读数（n=3/臂，方向性、非终局）：

1. **质量**：完成时两臂同级（0.90 vs 0.92–0.97）——边界句不提升判别质量。
   基线 0.94 的成因 = 残差句池 ~44 句固定，外层在探索轮里逐句语义判掉
   （枚举面）；强关键词规则只有 0.68，差值全是"外层亲自做语义"。
2. **完成率反向**：e0p 2/3 烧穿（e0 0/3）。边界句把行为推向更深/更长的
   分析（解剖：13 次 run_code 的分析管线、25 轮 22 shell 的广探索），
   在 8192×N 预算内更易触线。"更努力"而非"更聪明"。
3. **未观察到"试走 llm 撞诚实拒绝"**：e0p 的 run_code 用途全是分析/规则，
   没有撞保留名拒绝的戏剧场面——A③ 文字点名 lib/llm 路线在 gate-off 下
   不产生可观测的尝试行为（至少本批）。
4. **run_code 采用是deepseek 外层的自然行为**：gates 全关的基线臂也把沙箱
   当主力执行层（25–36 次调用 + writeVerified + 断言自校验）——M0 以来
   "沙箱作执行层"的采用不依赖 include/llm 门，产品假设获支持。
