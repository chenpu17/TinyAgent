# run_code 路由：离线轨迹分析与基线修正

日期：2026-09-11。性质：**纯离线分析**，只读相邻仓库 TinyAgentBench 已归档轨迹
（`results/runs/{ta-code-aw,ta-code-routing-v1|v2|v3-aw}/…`），零模型调用、零重跑、
不改 benchmark 状态。配套工具 `scripts/run_code_routing_trace.py`（用法：
`python3 scripts/run_code_routing_trace.py ../TinyAgentBench/results/runs/<arm>/<task>/r1`）。

本页不改变 v2 作为当前候选的结论，但修正三份既有报告中的两组被污染的对比数字，
并给 v4 提供数据支撑的单一变量设计。

## 1. 发现一：旧对照的"非缓存输入"被供应商缓存预热污染

proxy 账单里每个请求的 uncached = prompt − cached_tokens。旧臂 `ta-code-aw` 的
r1/r2 首请求 uncached 仅 ~1.6K（静态前缀 system+136 工具+任务提示 ≈ 21K 几乎全部
命中了批内/批间先前 run 留下的供应商前缀缓存），r3 才是真冷启动 21.8K：

| run | req1_unc | sum_unc | **conv_growth** | output | turns | wall(s) |
|---|---:|---:|---:|---:|---:|---:|
| 旧 awclean r1（暖） | 1,637 | 15,577 | 13,940 | 7,115 | 10 | 145.4 |
| 旧 awclean r2（暖） | 1,637 | 16,927 | 15,290 | 8,209 | 11 | 155.5 |
| 旧 awclean r3（冷） | 21,797 | 36,211 | 14,414 | 7,226 | 12 | 141.2 |
| v1 awclean（冷） | 22,402 | 40,070 | 17,668 | 11,574 | 10 | 331.1 |
| v2 awclean（冷） | 22,398 | 38,620 | 16,222 | 8,397 | 10 | 276.1 |
| v3 awclean（冷） | 22,528 | 34,233 | 11,705 | 10,632 | 11 | 258.7 |
| 旧 awlikesong r1/r2（暖） | 1,594 | 45,374 / 46,652 | 43,780 / 45,058 | ~17.9K | 16 / 23 | ~360 |
| 旧 awlikesong r3（冷） | 20,346 | 66,932 | 46,586 | 18,453 | 15 | 342.8 |
| v1 awlikesong（冷） | 22,359 | 35,121 | 12,762 | 7,347 | 17 | 222.7 |

定义：**conv_growth = sum_unc − req1_unc**，即首轮静态前缀之外的对话增量，
对缓存状态鲁棒（r1 暖/冷不影响它：旧 awclean 三次为 13.9K/15.3K/14.4K）。
路由臂均为隔离单跑，req1 全冷，彼此可比。

由此修正（原报告数字 → 冷启动可比值）：

| 原结论 | 原数字 | 修正后 |
|---|---|---|
| pilot 报告：awclean 非缓存输入 +136.7% | 40,070 vs 16,927（中位，两暖一冷） | **+6.6%**（v1 40,070 vs 旧冷 r3 36,211）；v2 为 +6.6% 同级 |
| pilot 报告：awclean 调 v2 后非缓存 38,620，+128%（对 16,927） | 同上污染 | **+6.6%**（38,620 vs 36,211） |
| pilot 报告：awlikesong 非缓存 −24.7% | 35,121 vs 46,652（两暖一冷中位） | **−47.5%**（vs 旧冷 r3 66,932）；conv_growth 口径 **−72.6%** |
| v3 报告：非缓存 −11.4% | 34,233 vs 38,620 | 维持成立（同冷可比），且是 v3 唯一改善项 |

结论改写：**代码路线在 awclean 上真实代价是 conv_growth +12.5%、墙钟 ~2×、
token 大致持平**，而不是"非缓存输入翻倍"；在 awlikesong 上收益比原先报告的更大。
墙钟回归与 token 持平仍是 awclean 形状任务的真实劣势（见发现三）。

## 2. 发现二：双重取数——对话级全量直取后沙箱又取一遍

v2 awclean 第 5 轮：5 个端点各一次 `page_limit=20` 直接调用（单页即全量），
22.2K 字符进对话（该轮新增 uncached 8,014，含助手消息），随后 run_code #1
在沙箱内重新分页收集同样数据。v1 awlikesong 第 4/6 轮同模式
（following_artists + liked_songs 全页直取 2,753 + search_songs 1,105）。

conv_growth 分解：

| 成分（v2 awclean，共 16,222） | token | 占比 |
|---|---:|---:|
| setup 轮（凭证/登录等） | ~890 | 5% |
| read_skill 技能正文（一次性） | ~4,100 | 25% |
| **第 5 轮全量直取（双重取数）** | **8,014** | **49%** |
| 3 个代码轮（响应+摘要结果） | 2,642 | 16% |
| 收尾轮 | ~305 | 2% |

| 成分（v1 awlikesong，共 12,762） | token | 占比 |
|---|---:|---:|
| setup 轮 | ~706 | 6% |
| 直取+搜索（双重取数） | 3,858 | 30% |
| read_skill 技能正文 | 3,972 | 31% |
| 7 个代码轮 | 3,269 | 26% |
| **尾部清理/重复 complete 4 轮** | **957** | 8% |

代码轮本身很便宜（摘要返回 ~0.2-1K/轮）。**可避免成本的大头是双重取数**：
对话里只需要字段名/信封形状/分页契约，全量收集应只发生在沙箱内。

## 3. 发现三：v3 失败的正确读法与 v4 的设计空间

v3 与 v2 唯一模型可见差异是提示词段落，但 v3 **跳过了对话级直取**
（conv_growth 11,705，三者最低），代价是第 5 轮无任何形状证据直接生成 4,404 字符
程序（单轮 output 4,324、92.1s），猜错字段（`.id` vs `song_id`/`album_id`）报错后
恢复分阶段。v2 全量直取 → 字段名正确 → 0 错误，但付了 8K 对话取数成本。

即三个样本恰好张出设计空间的两端：

| | 形状证据 | conv_growth | 错误 | output |
|---|---|---:|---:|---:|
| v2：全量直取 | 全部数据进对话 | 16,222 | 0 | 8,397 |
| v3：零证据直写 | 无 | 11,705 | 1 | 10,632 |
| **v4 目标：最小形状探测** | 1 页 1–2 条 | **~9K 预期** | 0（保留证据） | ~8K 预期 |

墙钟主因是模型生成长度而非沙箱执行（各 run 墙钟 ≈ 请求时长之和 ±3s；
v2 三个代码轮 65.6/32.0/62.5s，v3 失败轮 92.1s）。缩短"过早长程序"同时降
output 与墙钟；探测本身应当小而快。

## 4. 发现四：杂项

- v1 awlikesong 尾部 4 轮（write_file×2、list_dir、run_code、complete×2）做临时
  文件清理与补 complete，约 957 token + 4 轮墙钟；v2 的收尾纪律已部分缓解，仍值得
  在 v4 提示词中保留"文件只在续批/恢复/任务需要时保存"的既有条款（不新增）。
- 旧直取路线 awclean 的轮次方差 ±2（10/11/12）、output 7.1–8.2K：**单次探针的
  差异判定阈值应 ≥ 轮次 ±2、output ±15%**，否则视为噪声。×3 重复是后续任何
  A/B 的前置条件。
- 路由臂 req1_unc ≈ 22.4K vs 旧臂 21.8K：新描述+变体提示词的静态成本约 +0.6K，
  每次冷启动多付一次，暖缓存后摊薄——量级可接受，无需为此压缩系统提示词。

## 6. 对后续实验的约束（测量协议）

1. **每个 run 记录 req1_unc** 并写入结果 JSON；req1_unc < 2K 判为暖启动，
   uncached 对比中剔除或归一。
2. **跨 run 效率主指标用 conv_growth**；sum_unc、req1_unc、output、生成时长
   （proxy dur_ms 之和）分列报告。
3. 批量矩阵必须**随机交错 arm×task**（暖缓存期望上均匀命中各臂），仍逐 run 记录。
4. 单次探针的判定阈值：轮次差 ≥2、output 差 ≥15%、conv_growth 差 ≥20% 才算方向
   信号；正式结论一律 ×3 重复。
