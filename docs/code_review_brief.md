# code 特性扩展设计 · 评审导引（v0.7）

> 两份设计稿的阅读入口，当前规格以正文为准。代码核对基线为 master @ 0579564；
> 本轮修订没有实现验收、模型收益或可信部署的实测结论。

## 1. 产品方向与范围

面向宿主集成的轻量 Agent 执行内核，把重复语义任务转化为可检查、可维护的程序
资产，并验证其是否能在同等质量下节省总成本。首发验证选择只读工单分类/打标，
输出分类文件与待复核项；语料、质量阈值和收益门槛在 V0-A 配方中预登记。

| 能力 | 责任 | 文档 |
|---|---|---|
| llm | 沙箱内无状态单次模型调用、词表校验、预算与用量归因 | [code_llm_design.md](code_llm_design.md)，LD-1～19 |
| callBatch | 有界只读并行派发、逐项结果、共享 gate；不提供事务 | 同上 §4 |
| include | 文件库加载、登记内容一致性与默认流程准入、版本化质量证据 | [code_memory_design.md](code_memory_design.md)，MD-1～14 |

固定任务的节省证明程序摊销；变化任务中的正确发现、修订与放弃，才证明 Agent
增量。三项原语分别评估，不以一项成功为整个组合背书。

## 2. v0.7 的主要修订

| 议题 | 当前决定 | 验收位置 |
|---|---|---|
| 信任承诺 | 默认是可审计复用，不是来源认证；旧 draft 可经重新登记在新会话执行，明确记录限制 | memory MD-14、§5、A-M12 |
| 内容批准 | 新建/更新回 draft；会话资格绑定路径与 hash；可信部署保护批准依据及写入/执行通道 | memory MD-10/12/14、§5.2 |
| 质量政策 | 自测、固定探针、实际输出核验分开；场景定义阈值、抽样、升级、发布，无通用“抽 3 条即合格” | llm §6.3、A-L10 |
| 质量证据 | 绑定代码/依赖/覆写、模型、数据与业务标准版本；批准和质量状态分开 | memory §4 |
| 预算 | 估算预占不承诺 run 硬封顶；未知用量单列，实测 totals 不伪造；已结算 usage 不重复 share | llm LD-6/12/17、§3.1、A-L1/2 |
| 阶段依赖 | V0-A 用临时装置验证方法；最小实现后 V0-B 验证集成与生命周期 | llm §9 |
| 经济性 | 四路线公平对照；全部失败/重试/复核计入单位成功成本；工时与模型费分列，再按复用假设算 TCO | llm §8 |
| 恢复交付 | done 不代表 verified；按块预存 checkpoint，终止后不承诺补写，未落盘部分标待确认 | llm §6.3、附录 A |
| 核心边界 | 按执行责任与治理分工，允许文件/checkpoint 持久化；不建核心审批平台或持久 JS 堆 | llm §10.2 |

清理的旧结论：Git 提交不自动批准；固定 prelude 不是隔离边界；同 Provider 不保证
同数据接收方；include 不经过 readAll，不能沿用其单行分页限制；全局排序/按 ID
去重仍可程序化。

## 3. 实施与验证顺序

1. **V0-A 方法验证＋M0 有界探针**：使用现有工具与临时适配，预登记任务、留出
   数据、门槛与调优预算；原型成绩不代表 native 集成成本。
2. **M1～M3 最小实现**：include、callBatch、llm 的运行时与文案随阶段一起
   验证。测试是阶段出口，避免把未实现功能全量通过作为编码前置。
3. **M4 契约装配＋V0-B 集成验证**：跑 E0–E3 与外部四路线，覆盖固定任务、
   分布变化、规则/接口变化、不适用任务，计入发现/修订/审批的人工成本。
4. **扩展决定**：先满足质量和覆盖率底线，再判收益；可继续、缩小场景、保留
   独立能力、停止或判证据不足。Tier-2 在 V0-B 后另立项。

memory M1/M2 对应总路线 M1 的加载与模板工作；memory M3 指 Tier-2，区别于
llm M3。llm.enabled/include/call_batch 继续独立且默认关闭。

## 4. 复核重点

- 默认准入与宿主可信策略是否分清，限制反例是否如实验收？
- 实测、估算、未知用量能否区分，预算预占和结算是否恰好一次？
- 质量政策是否在正式数据开跑前冻结，是否包含覆盖率、少数类及失败升级？
- 新代码/新模型是否错误沿用旧批准或质量成绩？
- 四路线是否具有同等业务知识与调优机会，固定任务摊销是否被误当 Agent 增量？
- V0-B 是否计入真实人工维护/部署成本，失败与未知用量是否被排除或计零？

工程测试证明契约；产品价值依赖实测；可信部署还须在实际宿主权限和政策下
单独验收，不能由默认 include 测试推导。

## 5. 保留与不扩展的范围

保留：无状态单发、共享 Provider、labels、只读 callBatch、文件库、新堆执行、
宿主治理及默认关闭的评测门。LD/MD 编号稳定，正文以 v0.7 为准。

本轮不扩展：通用结构化抽取 API、跨 provider 路由、持久沙箱、核心资产数据库、
内建审批/质量引擎、长期调度和 Tier-2。金额折算由评测装置承担，核心价格引擎
不立项；parse-only 和描述扩容仍为后续评估项。
