### 裁决：假设成立

- 两实例 A' **均仍采用 run_code**：外层轨迹 `read_skill → run_code`（on_demand 发现
  路径真实走通），12 页 MCP 分页全部在 guest loop 内拉完（服务端日志跨度 0.0005s /
  0.0034s，外层 MCP 调用 0 次）——与 G2 原版 A 的承接形态同构（同 3 turns、同外层
  工具形状）。
- 两实例费用比 0.567 / 0.571 均 <0.8（工单 06 成立线），与 G2 原配方下的 0.554 /
  0.578 经济上不可区分——**去掉能力段没有吃掉 T2 的经济性信号**。
- 无 A' 失败-B 成功（推翻事件未发生；g2i1 的失败方向相反——B 臂失手，见下）。

### 附带读数（机制核对）

1. **A' 绝对费用 vs G2 原版 A**：g2i1 +55%（0.0246 vs 0.0158）、g2i2 +5%（0.0189 vs
   0.0179）——同 turns、同外层工具形状，差在 thinking/轨迹长度方差，非机制成本。
   G2C 在 T1 上「A' 比原版 A 便宜」的读数未在 T2 复现，但对本工单裁决无影响
   （裁决口径是与 B 的费用比，不是与原版 A 的差分）。
2. **B 臂 g2i1 失手**：11/11 行交付、ID 全对、单条计数错（u-0041 计 1 应 2）——模型
   质量方差，非装置故障（validation 结构完整、无 invalid/duplicate/unknown 行）。
   该失败把 B 的 token 推到 52,112（G2 同臂 41,457），抬高了本配对比值的分母；
   保守解读：0.567 若以 G2 的 B（0.0286）为分母则是 0.858——仍低于 1，但超过 0.8
   线。裁决按工单预写口径（本批配对 B）计，此敏感性如实登记。
3. **停止线与估算失误**：工单 06 写「按 G2 T2 水位预计 ~0.03 CNY」——实际 G2 T2 每
   对 ~0.045-0.049，四跑天然 ~0.09-0.12，停止线 0.1 是按错误水位设的（登记为工单
   撰写失误，非装置问题）。续批机制（schedule 取缺跑子集、配置哈希对账、账目结转）
   首次启用即按纪律工作。
