# run_code v4：最小形状探测探针

日期：2026-09-11。实验版本：`run-code-routing-v4`。

结论：官方判卷 3/3 通过、全量直取被消灭，但**模型轮次明显回归（中位 14 vs v2 的 8）、
工具名猜测失败模式未根除**；v4 不提升为当前候选，已恢复 v2 提示词与指纹。
实验提示词逐字归档在 `examples/prompts/experiments/agentic-code-v4.md`。

本实验是[离线轨迹分析](run_code_routing_analysis.md)的数据驱动后续：分析显示
v2 的对话增量成本大头是"全量直取后沙箱再取一遍"（占 conv_growth 49%）与代码内
工具名猜测，故设计单变量提示词修正。动机与阈值（轮次 ±2、conv_growth 20%）均在
跑模型前预先登记于分析文档 §6/§7。

## 改动（单变量）

仅替换 `agentic-code.md` 中"Choose how to execute"一节的一个要点：原文
"You may inspect an unfamiliar API directly first"（被模型执行为全量直取）改为
最小探测纪律——确认沙箱视角的工具名（`tools.list()`）、响应信封、条目字段名、
分页规则，1 页 1–2 条即可；禁止把整集合拉进对话做规划，全量收集/集合构造/计数
都在代码内完成。工具描述、teaser、技能全文、运行时与二进制均与 v2 逐字节一致。

## 实验条件

- 模型 `glm-5.3-flash`；awclean ×3；on-demand、precheck=false。
- 独立臂 `ta-code-routing-v4-r3-aw`；二进制 SHA256 与 v2/v3 相同
  （`7872a378…4622`，无 Rust 改动）；code prompt SHA256
  `51884b9ee2635d06643303131f0edd32dc6fea68bd72c129c874c332ba43ecc5`。
- 对照：同日 `ta-code-routing-v2-r3-aw` 批次（同任务 ×3、同二进制、同判卷）。

```sh
python3 scripts/run_code_routing_pilot.py --tasks awclean --repeats 3 --run
```

原始数据：相邻仓库 `TinyAgentBench/results/runs/ta-code-routing-v4-r3-aw/awclean/r{1,2,3}/`；
条件指纹在该臂 `pilot.json`。已恢复 v2，直接重跑会选回 v2 臂，不构成 v4 复现。

## 结果（均为 ×3）

| 指标 | v2 批次 | v4 | 判定 |
|---|---|---|---|
| 官方判卷 | 3/3 PASS | 3/3 PASS | 持平 |
| 模型轮次 | 7 / 16 / 8（中位 8） | **14 / 13 / 15（中位 14）** | **回归，超 ±2 阈值** |
| conv_growth | 11,586 / 11,772 / 9,263 | 12,627 / 13,520 / 12,503 | +8.6%，未过 20% 阈值，方向偏差 |
| output token | 7,391 / 7,013 / 8,437 | 11,800 / 6,397 / 5,267 | r1 异常高，r2/r3 反而低 |
| 全量直取轮 | 原 v2 单跑 8,014 tok；批次 r1/r3 无 | **3/3 无**（探测仅 209–1,155 tok） | **目标达成** |
| 工具名猜测错误 | 批次 r2 犯 1 次 | **r3 仍犯**（`spotify__show_song_library`） | 目标未达成 |
| 代码内错误 | 1–2 次/跑 | r1 两次"unexpected response shape"、r3 一次 | 持平偏差 |

## 轨迹观察

- r1：批量 3 端点 ×2 条最小探测（209 tok，纪律被执行）→ 但探测只覆盖 5 端点中的
  3 个，随后 4,414 字符大程序（单轮 output 5,502、113.2s）两次在代码内撞形状错误，
  中途重新 login，再 4 个程序收尾。**探测证据没有可靠迁移进代码**，且"探测→一次
  写全"重现了 v3 的过早长程序形态。
- r2：完全干净（0 错误）：read_skill → 583c 代码内探测 → 分阶段收集/执行/校验，
  但仍是 13 轮的小步节奏。
- r3：先猜工具名报错一次（提示词里的 `tools.list()` 未被遵循），恢复后 9 个小程序
  分步完成，15 轮。

## 判断

v4 在预先登记的判定标准下不过门：轮次回归明确，两大目标失败模式只消灭一个。
结合 v3（同次闭环压力→过早长程序）与本轮（最小探测→小步碎化+证据迁移不良），
**连续两个单变量提示词实验都在轮次上回归**——该模型的行为方差（同契约 4 样本
4 种路径）大于提示词微调的边际效应，继续叠提示词属于在噪声上择优。

剩余已知的真实成本：awclean 形状任务上墙钟 ~1.5×（长代码生成响应）、偶发全量直取
与工具名试错。它们出现与否由采样决定，提示词层面没有稳定的压制手段。

决定：保持 v2；提示词迭代到此为止；下一步按分析文档门控顺序做负例对照
（awlikes / awphoto，验误触发），再进入四臂矩阵。技能层面的"最小探测"示例
（类似 v2 的 responseRows 模式）留作未来单变量候选，本轮不做。
