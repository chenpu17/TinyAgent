## 1. 问题判断与证据边界

主要假设是：模型未稳定识别“剩余工作已经可程序化”的切换机会；旧文案的局部禁用条件、懒加载的准备成本、自然语言枚举集合的纪律共同偏向直接调用。不能据此断言模型训练中相关先验为零，也不能从可见轨迹未提及 run_code 推断模型从未考虑它。

实施前只读核对相邻 TinyAgentBench 的 `results/runs/*/*/r*/run.json` 和 `stdout.txt`。成功率读取 `verdict`，使用率按外层 `[tool →] run_code` 统计，非重新跑批：

| 本地观察 | 结果 |
|---|---|
| v4 `ta-code-aw` | 45/51 PASS；31/51 使用 run_code |
| v4 `ta-nocode-aw` | 37/51 PASS |
| `opencode-aw` 参照 | 45/51 PASS |
| eager 已覆盖的相同 21 个任务×重复组合 | on-demand 7/21 触发，eager 16/21 |
| 上述 21 个组合的正确率 | on-demand 21/21，eager 20/21 |
| awlikesong、awclean 各自 | on-demand 0/3 → eager 3/3 触发 |

数据取自 9 月 9 日的 on-demand 批次和 9 月 10 日的 eager 批次；21 个配对组合是 7 题×3 重复，完整 51 个 run 是 17 题×3 重复。没有将这些观察当作随机同期因果实验，也不据此宣布本次修复有效。相邻评测仓库未被修改。

eager 会合成 `assistant(read_skill)` 与返回正文的历史对，同时改变知识披露、显著性和行为历史，因此“eager 有效”不等价于“根因只有知识缺失”。本版保持该机制原样。

## 2. 已落地设计

### 2.1 以整个剩余流程为判断单位

工具描述、技能 teaser、正文入口与独立 code 提示词采用同一规则：

1. 筛选、参数构造和校验规则已经明确。
2. 剩余仍有跨页/较大集合的同构调用，或大量中间数据处理。

同时满足后，先加载 `read_skill({"skill":"run-code"})`（已在上下文中可用则无需重读），再让代码承接。主要只变化游标、页码或对象 ID 是结构线索；不会以“所有/批量”等量词或调用次数作为充分条件。

可先直接探查未知接口；结果揭示规模、分页信息或目标集合后重判，不等到失败或上下文耗尽。整个剩余任务一次工具调用或一条实际可访问数据源的 shell 管道即可完成时，直接做。小集合可直接批量调用；逐项语义判断留给模型，只有规则稳定的子流程进入代码。

运行时资源额度仍有数字，这是已有执行边界；它们不是模型选工具的触发阈值。

### 2.2 允许换轨，但不允许从头重放修改

技能与变体提示词要求保留谓词、目标 ID、游标和已完成/失败项，只续做未完成部分。不确定某次修改是否生效时，先查状态。每次 run_code 的 JS 变量不持久化，续批状态须显式传入或写文件。

### 2.3 协调自然语言计划与代码内集合

新增 `examples/prompts/agentic-code.md`，原 `agentic.md` 逐字保留。

实体层级、AND/OR 谓词与边界案例仍须在修改前以自然语言明确。大集合可以在代码/文件中构造，但必须在修改前检查精确 KEEP/ACT 集合及计数；当规则无歧义且操作已经授权时，收集、检查、执行可以在同一代码调用中完成，随后返回摘要。新收集的数据仍需模型判断或任务要求用户确认时，先返回计划，再执行。

原有独立调用批量发送的纪律保留；新增说明区分“调用顺序”与“循环放在哪里”。有依赖的重复操作可以在代码中串行执行，不必逐轮交给模型。

该变体仅供启用 run_code 的部署显式选择，不会自动加载，也不向 no-code 基线添加 run_code 指令。

### 2.4 修正会被放大的批量示例缺陷

独立检视发现旧示例把所有条目直接加入 targets；缺失 `items` 被当成分页结束；`okCount = targets.length - failed.length` 之后的对账恒成立；没有重查最终状态。提高触发率会提高此错误模板的曝光率，因此本次一并修复。

新示例明确声明虚构 API 的响应契约，实际使用必须按真实接口适配。示例覆盖严格分页、游标前进、跨页去重、重复项一致性、`archived AND !liked` 的 KEEP/ACT 划分、计划落盘、独立记账，以及逐项状态读回。成功响应却没有生效会报错；业务失败返回未完成摘要，不能冒充全成功。单页 SQL 聚合示例也明确“已经确认结果完整”的前提。

文档中定义的示例局部函数不是新增内置 helper。运行时 prelude、封闭 helper 清单、工具 schema、预检拒答与墓碑文案均保持原样。

### 2.5 同源同步与指纹

新增 `scripts/sync_run_code_contract.py`，从 Rust 工具定义和内置技能生成设计附录 A 及 `docs/run_code_routing_manifest.json`。清除了旧附录中重复的技能正文副本。

```sh
python3 scripts/sync_run_code_contract.py --write
python3 scripts/sync_run_code_contract.py --check
```

`--check` 检查附录/指纹是否与源码一致，以及描述≤1200字符、teaser≤1024字符。它是开发期同步检查，不进入 agent 运行流程。prelude 不承载触发文本；“同源同步”在这里指描述、正文、设计附录一致，并核对 prelude 能力契约未漂移。

本版描述 **1189 字符**，teaser **186 字符**。技能全文由 6096 增至 9184 字符，主要增加决策/恢复纪律与可验证示例。手册增长是实际成本，应计入 on-demand 与 eager 的 token 评测；字符数不等于 tokenizer token 数。

## 5. 项目方验证方案

### 5.1 先验证接线

记录实际请求里的 run_code 描述、技能 teaser、系统提示词；确认不是磁盘旧技能或旧二进制。检查原语/MCP工具集合、顺序、预算、模型、采样参数、最终判卷器保持预定条件。保存完整指纹，不静默覆盖旧批次缓存。

若继续原 S1 teaser-only 探针，应使用旧二进制和旧技能正文，仅替换其 frontmatter description；单独指纹归档。本次新版正文不能冒充“只改 teaser”的条件。

### 5.2 四臂主矩阵

以下四臂全部开启 run_code；独立 no-code 参照另行保留：

| 臂 | 契约/二进制 | 提示词 | skill_injection |
|---|---|---|---|
| A 对照 | 固定旧版 | 原 agentic.md | on_demand |
| B 仅 eager | 与 A 完全相同 | 与 A 相同 | eager |
| C 本次修复 | 固定本版 | agentic-code.md | on_demand |
| D 修复＋eager | 与 C 完全相同 | 与 C 相同 | eager |

A/B 必须使用同一旧契约，C/D 必须使用同一本版契约。**新版二进制搭配原提示词仍会带新版描述/技能，不能充当旧对照 A。** 若旧产物不可复现，用固定源码起点重建，并将其标为新的对照批；不能冒称与 v4 二进制相同。

本次包含批量示例质量修复，C−A 估计的是整个修复包的效果，不能解释为“仅触发句的纯效应”。需要机制分离时，额外在本版契约固定的条件下比较原提示词与变体；或在专门实验中固定技能正文，分别替换 teaser、描述。eager 的正文/显著性/合成历史效应仍未分离。

每题每臂至少 3 重复，交错运行并重置任务状态。对重点摇摆题增加重复优于把同题重复当成独立题数。保持 shell 与 MCP 工具面，不用删工具逼迫选择；当前历史评测若两臂原本工具面不同，须明确披露，不能把产品对比当成单变量因果比较。

### 5.3 预先标注任务形状与指标

在看新轨迹之前标注“适合代码的机械子流程”“小集合直接完成”“逐项语义判断”三个子集，标签不进入模型提示词。

第一层指标：任务正确率、越界修改、漏页/漏项、错误完成声明。第二层指标：适合代码子集的自主触发率、负例误触发率、有效代码覆盖的剩余工作比例、外层模型往返、输入/输出/缓存 token、墙钟。

“有效换轨”应让代码承接实际机械工作；只调用一次 `tools.list()` 或计算一个常量，不计作有效承接。换轨延迟从首个提供充分规模与规则证据的工具结果开始，计到首次有效承接；未触发记为未发生，不只报告触发样本的延迟均值。证据时点由离线标注确定；这不是 harness 注入提示。

把真实 `read_skill` 与 `eager-run-code` 合成历史分开；把外层 tool-call records 与 `meta.trace`/`call_count` 的沙箱内部调用分开。沙箱没有消除业务 API 工作。只对成功配对任务计算效率会产生选择偏差，需同时报告全体预算消耗/失败分布和双方成功子集；失败、超时样本不得丢弃。

保留官方结果分，使用“同等正确率下的成本”或不同 token/轮次预算下的成功率曲线衡量收益。按任务聚合或按任务聚类计算区间；17 题×3 重复不能当作 51 个独立任务。正确率下降且无明确预算收益时，不以触发率上升宣布胜出。

### 5.4 2B 数据采集与语言轴

本版保留英文系统纪律、中文工具/技能的既有语言，避免同时引入语言翻译因素。若要评估语言轴，另开语义等价的全中文/全英文变体，固定其余条件并按任务类型验证；不能预设全中文必胜。

契约执行样本可来自 eager，但必须标明合成历史，并在训练时避免把预置 assistant 的 read_skill 当成自主决策标签。触发样本优先采集部署一致的 on-demand 完整链条：规模/规则证据 → 自主读取技能 → 有效编排 → 状态验证，包含中途换轨及失败恢复。

同时采集量词相同但规模小、集合大但逐项需语义判断、可直接用真实可达 shell 管道完成的对照样本。按任务族切分训练与测试，避免把同题不同重复分到两侧。样本占比用部署形态的漏触发/误触发/正确率与 token 指标调节，本次不把无实证的固定百分比写成配方。

所有新样本打 `run-code-routing-v1` 和实际 manifest/模型/配置/注入形态版本戳。旧契约数据保留原版本，不能静默混入新基线。eager 是采集与对照形态；最终 on-demand 部署必须重新验收，不能直接继承 eager 的成绩。
