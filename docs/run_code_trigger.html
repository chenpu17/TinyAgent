TINYAGENT · RUN_CODE

run_code 什么时候会被触发？

没有程序化触发器——模型根据已知规则与剩余工作规模选择执行方式。 工具描述和技能简介常驻，完整技能按需加载；本图说明候选决策规则，效果仍需评测。

前置假设（本图不展开）：cargo feature 已编入 · code.enabled = true · 顶层 agent（task 子 agent 看不到 run_code）
01 · 谁在决定

没有触发器，只有模型的判断

代码里不存在任何「满足 X 就自动启用 run_code」的规则。每一轮对话， 模型都能看到 run_code 的工具描述；探查结果揭示规模时，应重判剩余流程。 系统能做的是把「什么该用、什么不该用」的判别标准写在模型可见的三个信号面里。

三个引导信号面

  • 工具描述（≤1200 字符）：随每次请求的工具 schema 下发——身份、环境、封闭的助手清单、返回纪律、「何时用/何时不用」的判据都在这。
  • 内置技能简介：技能名 run-code + 触发式简介常驻 system prompt（≤1024 字符），提示何时加载。
  • 技能正文：深契约（read_file 三模式、字节保真复制、批量闭环模板、BigInt 纪律）不进 schema，识别到合适的剩余流程后经 read_skill 加载，包含迁移进度与批量校验纪律。

为什么这样设计

描述瘦身是因为工具 schema 每次请求都要付 token——把「什么时候用」的判断依据放进描述， 模型每一次做决策时都拿着同一份规则；细节则移到可压缩、可回收的技能正文。 描述、技能正文、设计文档附录 A 三处同源同步，改动必须三处一起动。

双条件：
规则已明确，且剩余仍有跨页/大量对象的同构调用或大量中间数据处理。
02 · 决策树

按整个剩余任务选择执行方式

先直接探查未知接口，拿到规模与返回形状后重判。右边须同时满足规则稳定与剩余规模； “所有/批量”不是规模证据。独立调用的并发与代码内依赖调用的串行并不冲突。

模型收到一个任务（run_code 可见）
开工时及探查揭示规模后重判：剩余流程适合直接调用还是代码？
直接完成 / 继续探查
以整个剩余任务为判断范围
单步可完成

整个剩余任务一次调用能做完

读/写一个文件、改一处代码、跑一条命令——直接调 read_file / edit_file / shell，更省更稳。

管道可完成

一条可用 shell 管道能做完整任务

排序、去重、求和、过滤——shell 必须实际能访问数据源；MCP-only API 不能假设可经 shell 调用。

小规模同构

小集合或逐项仍需语义判断

小集合可直接批量调用；逐项语义判断留给模型，仅把规则稳定的子流程交给代码。

无工具需求

问答 / 写作 / 分析类任务

纯生成型任务连工具都不一定需要，run_code 自然不会进入考虑。

加载技能 → 代码承接剩余流程
规则明确 AND 剩余有规模；不设触发次数阈值
循环 / 批量

跨页 / 大集合中的同构调用

后续主要改变游标、页码或对象 ID；先加载技能，再写循环。换轨时带入谓词、游标、已完成项，只续做未完成部分。

大文件加工

数据装不进对话上下文

readAll 整读后聚合/过滤/统计，只 return 摘要。实测对照：不用代码时模型退回 17 次手动翻页，把 run 级 token 预算烧穿在重读历史上。

多步 / 关联

跨文件 join、分组、JSON 嵌套处理

多步数据加工的中间结果留在 JS 堆里（受内存上限约束）不进对话；代码经 JSON 直传，免去 shell 转义烦恼。

批量闭环

确定集合 → 执行记账 → 状态读回

大清单留在变量/文件，修改前检查集合与计数；需进一步判断或确认时先返回计划。执行后重查实际状态与保留集合；预算不足时分批持久化，状态不明的修改先查后重试。

规则明确且剩余有规模，就加载技能并让代码承接；整个剩余任务可直接完成时直接做。 code 专用提示词变体见 examples/prompts/agentic-code.md；原 agentic.md 保留作对照。 收益以正确率、模型往返与 token 联合验证，不能把沙箱内部 API 调用当成消失。
03 · 触发之后

被调用 ≠ 一定跑完

模型一旦决定调用，还有一组运行期闸门。这些是终止与拦截，不是触发决策—— 但用户看到「调了却报错」时，原因都在这里。

⏱

入口门：启动前直接拒

取消标志已置位 / 墙钟已过 → 沙箱不启动，燃料消耗为 0。短任务在单个检查间隔内就能跑完，所以必须先过这道门。

✋

拦截层：单条调用被拒

hooks Deny、deny_paths 命中、写出工作目录、写穿符号链接——单条调用报错可 try/catch，不影响后续调用。

🧮

调用额度：默认 200 次/次

每次执行独立计满、不跨次累计；失败和写错名的调用也照扣。超限即终止本次执行，报错文案引导分批落盘续跑。

⏳

墙钟 / 燃料 / 内存 / 栈

timeout_secs（与父 run 剩余时间取紧）、fuel 确定性预算、mem_mb 线性内存、384 KiB wasm 栈——任一超限强制终止，已写盘文件保留。

🛑

取消：宿主可随时打断

Ctrl-C / Esc 置位取消标志，约 10ms 内在下一条 wasm 指令处停下；在飞的内部工具调用会跑完。终止原因如实归因。

📦

结果纪律：返回值必须紧凑

只 return 摘要（统计数字、路径、样例行）；大数据写文件后返回路径。返回值与 console 日志共享尺寸上限，超限截日志保返回值。

审计不缺位：无论正常返回还是被终止，每次执行的内部调用逐条进审计 trace （名称 / 成败 / 耗时 / 输入哈希），连同调用计数、fuel 消耗一起落进 result.json 的 meta——跑到哪一步停的，事后都查得到。
