## 工单 01：G0 装置先行，禁止付费模型调用

**目标**：证明测得准、记得全、两臂公平，准备三题六跑；不在本工单证明特性有价值。

按以下顺序交付：

1. 记录 HEAD、工作树、二进制及历史 E0–E3/r2 配方指纹；不修改历史配方。
2. 实现版本化严格验收器，覆盖方案 §5.1 的全部坏产物；费用账包含失败、缓存与未知用量。
3. 准备 T0/T1/T2 三个小实例：12 条单文件、128+256 条本地关联、80+160 条双源分页。先用许可入口上的确定性参考程序解出，封存数据/任务/schema。
4. A/B 只改变现行 code 可用包；三原语全关，同模型，同公共提示词。T0/T1 两侧都有 shell，T2 两侧都没有。
5. 实现默认 dry-run 的最小 runner、独立状态、不可覆盖的 run_id、六跑固定顺序及最多四跑储备；不存在总是跑完 G2 的默认参数。
6. 用 mock provider 检查一次正常交付、一次失败和一次缺 usage；验证失败有记录、未知消耗不变成零、产物缺失不被跳过。
7. 冻结 manifest，包括真实注册工具、提示词差分、模型标识、实际价表、币种、费用停止值、软 token 闸及在途超额边界。
8. 复核人核对一对完整轨迹/账目、所有异常及权限；提交 G0 一页报告，停在交接点。

**约束**：不调共享提示词，不加 inner llm/include/callBatch，不构建恢复 runner，不放大数据，不跑模型档位矩阵，不访问真实业务写 API。若发现产品 bug，单列定位证据与最小修复，不伪装成评测配方更新。

**验收**：方案 §4.2 六项均有命令/工件证据；`paid_model_requests=0`。装置或环境不合格就报告阻塞，不用真实模型绕开。
工程时间盒先设两个人日；未完成就回报剩余项和工时，不要求仓促放行，也不自行扩成通用评测平台。

可复用的当前源码：

- `examples/mcp_echo.py`：stdio MCP；`examples/mock_openai.py`：provider mock，二者用途不同。
- `scripts/v0b_eval.py`：启动与结果字段参考；不得继承旧 score 的宽松接受或 aggregate 的 partial 排除。
- `tests/run_code_skill.rs` 与 `src/tools/run_code.rs`：分页/副作用/hook 定向测试。
- `docs/run_code_routing_matrix.md`：历史失败类型，不能当本轮开关对照数据。

## 工单 03：诊断储备（可不执行）

全 G1 总计不超过 10 runs，储备最多 4 runs。不要把不同诊断各做四次。

派工必须写：观察 → 单一原因假设 → 将改哪个变量 → 哪个结果推翻假设 → 具体 run_id 配方 → 费用余额。

仅可从以下动作选一个主方向：原配方完整配对复跑；强制 code 的独立诊断；一个候选修订后 T2 配对加一个负例配对。修装置后的重跑也占储备。
强制诊断与旧自然结果分栏；候选改动后重新冻结，保留原记录。第四次追加后结束，不追加“最后再确认一次”。

## 工单 05：G2C 候选修订验证——披露按需化（G2 报告派生，另行放行）

G2 报告（`g2-20260924-r1-report.md`）的下一可证伪假设。派工六要素：

- **观察**：T1 两实例累计费用比 1.372 >1.2 超线，且 A 臂 run_code 零采用（shell 直解、工具轨迹与 B 同构）；超线来源 = 披露固定开销（首请求输入差两实例完全一致 = 1529 tok：能力段 1974 字 + 技能 intro 351 字 + 3 工具 schema 2553 字）+ 披露引发的更长 thinking（g2i2 的 output 差占费用差 58%）。
- **单一原因假设**：T1 超线由「首请求即披露能力」引发；若能力段从系统提示词去掉（披露按需化——工具 schema 与 on_demand 技能索引保留，模型仍可自然发现 run_code），A'/B 首请求输入差从 1529 tok 降至 ~工具 schema 面，T1 费用比回落 ≤1.2。
- **将改哪个变量**：仅 A 臂系统提示词（去掉能力段，== 冻结公共段）。经实验配置显式门控（`build_config(candidate=True)`），不动共享提示词文件 `agentic-code.md`，不改已关档的 G1/G2 配方；code.enabled / 工具面 / on_demand 技能索引全部不变。
- **哪个结果推翻假设**：任一实例费用比仍 >1.2（披露不是主因，或 thinking 冗长不由披露引发）→ 推翻，维持 G2 的缩窄裁决；A' 出现交付失败而 B 成功 → 候选引入质量回归，同样推翻。
- **具体 run_id 配方**：T1 类同两实例（g2i1/g2i2，沿用 G2 实例使 A' 与 G2 原版 A 可直接配对差分）× A/B = 4 runs：`t1-g2i1-A', t1-g2i1-B, t1-g2i2-B, t1-g2i2-A'`（第一实例 A'B'、第二实例 B'A'，位置偏置控制同 G2 纪律）。判卷沿用实例级 g2_gold + digest 对账。
- **费用余额**：计划包络 4×80K = 0.32M；按 G2 T1 水位（~0.006 CNY/run）预计 ~0.025 CNY，停止线 0.1 CNY。联合封顶余量 1.42M（已用 337,982 / 1.76M），先行读数 = G1+G2 ledger 现算。

裁决规则（预先写定，不中途调）：两实例费用比均 ≤1.2 且无 A' 失败-B 成功 → 假设成立，候选进入 G3 分支评估（是否值得把按需披露作为默认装配）；任一超线或质量回归 → 推翻，维持缩窄裁决，停止此候选线。旧候选（G2 原版 A）数据在 `g2-20260924-r1/` 分栏保留，不覆盖、不混算。

## 工单 06：G3 分支验证——按需披露装配下的 T2 采用（G2C 报告派生，2026-09-27 放行）

G2C 报告（`g2c-20260925-r1-report.md`）的 G3 分支自然候选。派工六要素：

- **观察**：G2C 验证了披露按需化把 T1 负例拉回线内（1.372→1.098，两实例 1.013/1.182），且 T1 上 run_code 零采用不变。但 T2 的经济性信号（G2 两实例 A/B = 0.55/0.58）来自 run_code 的真实采用，而原装配的 A 臂能力段含「何时用 run_code」的指引——候选去掉能力段后，T2 的采用是否仍发生未经本轮验证。这是「按需披露能否作为默认装配」的最后一块未测面。
- **单一原因假设**：T2-A 的 run_code 采用不依赖能力段指引（on_demand 技能索引 + 任务形态本身足够引导采用）；按需披露装配下 T2 两实例 A' 仍采用 run_code，费用比维持 <0.8。
- **将改哪个变量**：仅 A 臂系统提示词（与 G2C 同款 `build_config(candidate=True)`，== 冻结公共段）。t2 场景的 MCP 数据源、实例、判卷、工具面、code.enabled 全部沿用 G2 冻结配方；不动共享提示词文件，不改已关档的 G1/G2/G2C 配方。
- **哪个结果推翻假设**：任一 T2 实例 A' 不再采用 run_code（工具轨迹无 run_code 调用或空承接），或费用比回升 >0.8 → 按需披露不可作为默认装配，维持「T2 类显式开启 + 能力段披露」的现状分仓。A' 交付失败而 B 成功 → 质量回归，同样推翻。
- **具体 run_id 配方**：T2 类同两实例（g2i1/g2i2，沿用 G2/G2C 实例使 A' 与 G2 原版 A 可直接配对差分）× A/B = 4 runs：`t2-g2i1-A', t2-g2i1-B, t2-g2i2-B, t2-g2i2-A'`（第一实例 A'B'、第二实例 B'A'，位置偏置控制同 G2 纪律）。判卷沿用实例级 g2_gold + digest 对账；MCP 数据文件批次内封存（同 prepare-g2 的 g2-data/ 铺设）。
- **费用余额**：计划包络 4×80K = 0.32M；按 G2 T2 水位预计 ~0.03 CNY，停止线 0.1 CNY。联合封顶余量按 G1+G2+G2C ledger 现算（G2C 报告口径已用 384,040 / 1.76M，余 ~1.38M）。

裁决规则（预先写定，不中途调）：两实例 A' 均仍采用 run_code 且费用比 <0.8、无 A' 失败-B 成功 → 假设成立，按需披露可作为默认装配候选（是否切换默认仍属产品决策，另行裁决）；任一实例 A' 零采用、费用比 >0.8 或质量回归 → 推翻，维持现状分仓，停止此候选线。G2 原版 T2 数据在 `g2-20260924-r1/` 分栏保留，不覆盖、不混算。
